# 이 앱은 무엇인가

`DECISIONS.md` 가 **어떻게 만들었나**라면, 이 문서는 **무엇을 만들려 했나**입니다.
과제 요구사항을 채우는 것과, 쓸 만한 것을 만드는 것은 다른 일이었습니다.

---

## 1. 정체성

> **날씨를 정보가 아니라 하루의 준비물로 번역하는 앱**

기온 숫자를 보여 주는 것이 목적이 아닙니다. `28℃` 를 알려 주는 앱은 이미 많습니다.
이 앱이 답하려는 질문은 다릅니다.

```
오늘 뭐 입지?      →  기온 구간에서 옷차림을 파생
오늘 뭐 듣지?      →  하늘 갈래에서 플레이리스트를 파생
지금 여기는?       →  GPS 로 가장 가까운 도시를 기본값으로
내가 보고 싶은 곳? →  검색으로 전국·해외 어디든 담기
```

히어로 화면의 세로 순서가 그 이야기를 그대로 합니다.

```
        28℃           ← 몇 도인가
      햇살 가득        ← 어떤 하늘인가
   HOT · 25°C ABOVE
   ‹‹  ▶  ››  SUNNY   ← 그래서 무엇을 들을까
      Outfit ⌄        ← 그래서 무엇을 입을까
```

**"전국 20개 도시" 가 아니라 "내 도시들"** 이라는 점이 마지막 조각이었습니다.
남이 정해 준 목록을 보는 앱과, 내가 담은 곳을 보는 앱은 성격이 다릅니다.

---

## 2. 처음 생각과 달라진 것

### 지역 추가 — "좌표표를 직접 만들어야 하나?"

처음에는 전국 시·군 좌표표를 손으로 만들 생각이었습니다. 229곳을 적어야 하고,
그러면 여전히 "누가 정해 준 목록" 이며 해외는 못 담습니다.

OpenWeatherMap 의 Geocoding 을 쓰면 표가 통째로 필요 없다는 걸 알고 방향을 틀었습니다.
다만 **한글 검색이 반쪽**이라(전국 135곳 중 116곳만 성공) 실패하는 것만 모아
스무 줄짜리 보정표를 만들었습니다. "전국 명부" 가 아니라 "안 걸리는 것들" 입니다.

### 대표 도시 — 핀을 만들었다가 걷어냄

"이 도시를 대표로" 를 지정하는 핀을 카드마다 달았습니다. 그런데 즐겨찾기 순서를
"최근에 담은 것이 맨 앞" 으로 바꾸자, **맨 앞이 곧 대표**가 되어 핀이 할 일이
없어졌습니다. `pinStore` · 핀 아이콘 · 정렬 예외를 전부 지웠습니다.

기능을 더해서 좋아진 것이 아니라, **덜어내서 좋아진 경우**였습니다.

### 위치와 즐겨찾기 — 무엇이 먼저인가

한때 즐겨찾기를 우선했습니다. "사용자가 명시적으로 정한 것이 상황보다 우선" 이라는
논리였는데, 날씨 앱의 관습(현재 위치가 기본)을 이기지 못했습니다.
즐겨찾기는 어차피 목록 맨 앞에 있어 한 번만 누르면 되므로 잃는 것이 없었습니다.

### 첫 방문 권한 요청 — 반대했다가 뒤집음

"맥락 없는 팝업은 거부율이 높다" 는 일반론으로 버튼 방식을 주장했습니다.
하지만 **날씨 앱은 위치가 핵심 가치**라 진입 시 묻는 것이 오히려 관습입니다.
애플 · 구글 · 네이버 날씨가 전부 그렇게 합니다.

## 3. UX 에서 지킨 것들

### 새 모양을 만들지 않는다

이 앱에는 색이 흑백 두 벌뿐이고, 채우지 않고, 1px 헤어라인으로만 구획을 나눕니다.
기능을 더할 때마다 그 규칙을 지켰습니다.

| 더한 것 | 새로 만든 도형 |
| --- | --- |
| 음악 조작 줄 | 없음 — Outfit 버튼과 같은 캡션 말투 |
| 이퀄라이저 | 없음 — PixelIcon(닷매트릭스)과 같은 네모난 점 |
| 통신 실패 표시 | 없음 — 테두리를 밝힘 (선택된 카드 · HOT 배지와 같은 방식) |
| Element Plus | 없음 — 라이브러리 CSS 변수를 앱 토큰에 연결 |

▶ 버튼에 원 테두리를 둘렀다가 뺐습니다. 바로 위 HOT 배지가 이미 알약이라
둘이 겹쳐 보였습니다. **크기와 밝기 차이만으로 위계를 만듭니다.**

### 아이콘만으로는 말하지 않는다

`⊙` 하나만 뒀을 때 "이게 뭔데?" 라는 반응이 나왔습니다. 조준점은 지도 앱에서
흔한 기호지만, 처음 본 사람은 모릅니다. 툴팁은 마우스를 올려야 보이고 터치
기기에는 아예 안 뜹니다. **`⊙ 내 위치` 로 글자를 붙였습니다.**

검색 후보의 `+` 도 같은 이유로 `＋ 담기` 가 됐습니다.

### 앱의 사정을 사용자에게 떠넘기지 않는다

처음에는 검색 결과가 없으면 **"찾아 담기" 버튼을 한 번 더** 누르게 했습니다.
API 호출을 아끼려는 우리 사정이었습니다.

사용자가 '속초' 를 친 순간 "속초를 찾겠다" 는 의도는 이미 끝났습니다. 버튼을 없애고
조건(담긴 목록에 없을 때만 · 두 글자 이상 · 0.5초 디바운스)으로 호출을 줄였습니다.

다만 **담는 것은 여전히 누릅니다.** 후보가 저절로 뜨는 것과 저절로 담기는 것은
다릅니다.

### 화면이 저 혼자 움직이지 않는다

위치 조회는 몇 초 걸립니다. 그 사이 사용자가 카드를 눌렀다면 뒤늦게 도착한 위치가
그 선택을 덮지 않습니다. 되돌릴 수 없는 동작(✕)은 hover 때만 보이고, 되돌릴 수 있는
동작(별)은 항상 보입니다.

### 실패를 숨기지 않되, 묻지 않은 것은 알리지 않는다

| 상황 | 처리 |
| --- | --- |
| 통신 실패 | 상태바에 `OFFLINE` + 다시 시도 버튼. 저장된 값으로 그리고 있음을 밝힘 |
| 자동재생 차단 | ▶ 를 그대로 남김. 실제 상태와 버튼이 어긋나지 않게 |
| 위치 오차 25km 초과 | 조용히 무시. 사용자가 요청한 적 없는 동작이라 |
| 사용자가 누른 위치 요청 실패 | 안내함. 거부와 그 밖을 나눠서 (거부는 브라우저 설정을 열어야 풀림) |

## 4. 과제와 무엇이 다른가

과제 요구사항은 **문법을 쓰는 것**이 목표입니다. `v-for` 를 써라, 컴포넌트를 나눠라,
store 를 만들어라. 그것만 채우면 "돌아가는 코드" 는 나오지만 "쓸 만한 앱" 은 아닙니다.

| 과제가 요구한 것 | 이 앱이 더 한 것 |
| --- | --- |
| Mock 배열을 `v-for` 로 출력 | 20곳이 아니라 **사용자가 담는 목록** — 검색 · GPS · 삭제 |
| 25℃ 기준 HOT/COOL 배지 | 기상청 구간표로 **옷차림 8단계** 파생 |
| 검색어로 필터링 | 목록에 없으면 **Geocoding 으로 찾아 담기** (한글 보정표 포함) |
| `axios` 로 API 한 곳 호출 | **API 넷** — 날씨 · 예보 · 지오코딩 · 역지오코딩 + 브라우저 Geolocation |
| store 하나 (온도 단위) | **store 넷** — 각각 "왜 store 인가" 를 두 질문으로 검증 |
| 로딩 / 실패 표시 | 실패를 **상태로** 들고 있음 (문구는 덮이지만 상태는 안 덮임) + 재시도 |
| — | **날씨별 플레이리스트** (YouTube IFrame Player API) |
| — | **다크/라이트 · 스플래시 · 반응형** (모바일에서 카드 접기) |

**store 를 하나 지운 것**도 여기 적습니다. 요구사항은 store 를 만들라고 하지,
지우라고 하지 않습니다. 기준을 세우면 지울 근거도 함께 생깁니다.

## 5. 모바일에서 쓰는 것을 전제로

폰에서 열 일이 더 많은 앱이라 좁은 화면을 예외가 아니라 기본으로 봤습니다.

- **860px 이하** — 2단이 1단으로. 카드 영역의 자체 스크롤을 풉니다.
  페이지 안에 또 스크롤이 있으면 손가락이 어느 쪽을 미는지 모호해집니다
- **카드 6장만** 보여 주고 나머지는 접습니다. 20장이 세로로 쌓이면 예보까지 한참
  내려야 합니다. 즐겨찾기가 맨 앞에 오므로 자주 보는 도시는 접힌 채로도 보입니다
- **560px 이하** — 히어로의 테두리를 걷어냅니다. 원본 목업이 원래 폰 화면이었고,
  좁아지면 그때의 "여백만 있는 검은 화면" 으로 돌아갑니다
- **터치 기기에서는 자동 포커스를 하지 않습니다.** 가상 키보드가 화면 절반을 덮고
  스크롤이 튑니다 (`pointer: fine` 조건)
- **긴 이름 줄바꿈** — `word-break: keep-all` 로 어절을 지키되, 한 어절이 카드보다
  길면 강제로 끊습니다 ('도쿄 하네다국제공항')
- GPS 는 폰에서 진짜 GPS 칩을 씁니다. 데스크톱(WiFi·IP 추정)보다 훨씬 정확합니다
